# Project agent memory

This public repository is the frontend and product home for Eddie's Wallet. Keep client behavior aligned with the product requirements in `docs/product-requirements.md`, especially split-audience money language, parent/child permissions, and offline states. The root `README.md` is the public landing page; keep its status, setup, and limitation claims truthful for an unfinished, unreleased MVP.

The app's service implementation and operations are maintained separately. Keep this repository frontend-only: do not add backend source, migrations, credentials, deployment assets, or infrastructure configuration here.

Brand and interface guidance lives in the project skill at `.agents/skills/eddies-wallet-design/SKILL.md`; load it before changing visuals, copy, or assets. `.claude/skills` is a tracked relative symlink to `.agents/skills`, so keep skill directory names matching their `name:` frontmatter and keep file names exact-cased for case-sensitive checkouts.

Releases ship through release-please and a captain-merged release PR that uploads to TestFlight; `docs/release.md` is authoritative for the pipeline, including the pull-request Release compile regression, version lineage, trust boundaries, and Apple-side setup. `docs/app-store-configuration.md` is authoritative for the live App Store Connect state of the optional Cloud subscription - products, prices, plan type, grace period, notification URLs, and what is deliberately still unproven. Apple account-level setup is shared across several apps and already satisfied; never request an agreement, tax/banking, upload API key, or distribution certificate again, and keep `EddysWallet/Configuration/EddysWallet.storekit` in step with that record. Merging a release PR is the release trigger and belongs to the captain alone. `test/release-checks.sh` guards the workflow invariants, state-aware release-please lineage (pre-first `0.0.0` seed + `initial-version: 0.1.0`, and post-first advanced seed matching available CHANGELOG/tag lineage), and version derivation; run it (plus the normal test suite) after touching anything under `.github/`, `ExportOptions.plist`, `release-please-config.json`, `test/fixtures/release-lineage/`, or the version files release-please owns (`version.txt`, `.release-please-manifest.json`, `CHANGELOG.md` - never hand-edit those three).

The app is kid-first: the child's read-only wallet is the root, and parent access is a transient in-memory elevation (`WalletStore.elevation`) that must never be persisted or survive backgrounding. `docs/product-requirements.md` owns split-audience money language, external-brand placement, child-personal everyday chrome, Parent terminology, and excluded product surfaces; brand and profile-derived runtime strings live in `ProductBrand` and `ChildProfileCopy`. Cloud runtime write settlement lives in `CloudWalletRepository` and the replica metadata in `LocalWalletRepository`: a persisted replica must first confirm its revision with a successful server read, at most one exact request, revision, and idempotency key may remain unresolved, and neither another write nor a Cloud-to-local handoff may proceed until stable server entry identity or accepted revision proves observation. `EddysWallet/README.md` owns wallet-read concurrency, publication ordering, Cloud write guards, review clearance, scheduled-money derivation and catch-up, local apply-on-read settlement (`LocalWalletRepository.applyDueScheduledSettlements`, cap, skip-and-wait, no Cloud auto-write, `WalletStore.submit` still requires elevation), and the transport-failure contract; keep every published-state branch in `WalletStore.performRead` aligned with it. Allowance and loan schedules share the same occurrence-chain shape in `WalletModels` (`AllowancePlan.occurrences` / `LoanSchedule.occurrences`: at most one `scheduled`, recorded rows name their entry); import still hashes only the allowance chain head on `allowanceRule`. A failed request must keep the failure it hit: `TransportDiagnostic` owns the privacy-safe shape, `WalletStore.connection` says only what that shape proves - the app never claims "offline" unless the device itself reported no network, and never claims any connection trouble at all once the service answered - and the raw detail stays behind the parent PIN in `ConnectionDetailsView`, never on the kid home. `KidCopy.statusBanner` is the kid home's whole status derivation and must stay a total function of `WalletConnection`, so no error may reach a kid as a reachability claim the read did not prove. Parents edit the child nickname only inside the Parent area (`EditChildProfileView` / `WalletStore.updateChildProfile` via `PUT /v1/child`); the kid home never exposes profile editing. Parent action buttons use `ActionButton`/`ActionButtonMetrics` with one continuous rounded geometry for fill and hit target - do not reintroduce `.buttonStyle(.bordered)` behind a mismatched card background. Parent PIN entry never scrolls - `ParentGateView` sizes the keypad to the screen and reserves its status line - and every `MoneyFlowView` step pins its primary action in a bottom safe-area inset so no confirm control can fall below the fold; both own those contracts in their own doc comments. Signed-in simulator and UI-test states use the Debug-only launch seam in `EddysWallet/DebugScenarios.swift`; that file owns its supported environment variables, and tests must never use real accounts. The `cloud-live-parent` scenario is the only one that composes the real `CloudWalletRepository` (over `SyntheticCloudTransport`, in process, no network), so drive genuine Cloud read, replica, and write-readiness behavior through it rather than a scripted repository that can only pose as one. Follow the evidence-directory environment contract documented on `EvidenceCaptureUITests` when capturing labeled screenshots. The shared scheme's `StoreKitConfigurationFileReference` only applies when Xcode itself launches the app: under `xcodebuild` (so all of CI) StoreKit ignores it and resolves the live App Store sandbox catalog over the network, so UI tests must never bound how long a product query takes - wait for the diagnostics surface to leave `CloudDiagnosticsStatus.loading` and judge the terminal status, as `terminalStoreKitDiagnosticsStatus` does. Every `HTTPTransport` test double must be genuinely thread-safe: `data(for:)` is nonisolated and `WalletStore` starts unstructured refresh tasks, so the app reaches a double from several cooperative threads at once exactly as it reaches `URLSessionTransport`, and unsynchronised stored properties corrupt their own buffers and kill the test host with SIGSEGV instead of failing an assertion. When a test process exits with no reported failure, rerun with `-enableThreadSanitizer YES` scoped to the named test before suspecting the runner. Every command-line or automated build or test that boots or runs an iOS simulator device - local, agent, and CI - runs through `test/sim.sh`, never a hand-made device: it owns reaping, creation, boot, a bounded timeout, and guaranteed teardown of one run-scoped device plus its XCTest clone, and `test/sim-lib.sh` owns that contract. Manual Xcode sequences use the developer's interactive simulator and are outside the wrapper. Device-less SDK compiles using `generic/platform=iOS Simulator` are also exempt because they boot and create no device. CI routes device-backed simulator work through the wrapper, `test/check-sim-usage.sh` checks the public wrapper boundary, `test/sim-lib-test.sh` behaviorally tests run-scoped teardown, and code review guards against future unwrapped simulator commands. `EddysWallet.xcodeproj/project.pbxproj` is hand-maintained with deterministic hex IDs; follow the existing ID conventions when adding files or targets.

Cloud capability behavior and client session presentation are documented in `EddysWallet/README.md`; the live StoreKit/backend distinction is owned by `docs/app-store-configuration.md`. The StoreKit and Cloud-recovery readouts never ship: both are Debug-only and reachable solely through `EW_UITEST_DIAGNOSTICS=1` (`DebugLaunchScenario.showsDiagnosticsEntryPoints`). The only shipped readout is the parent-only connection detail above, and it appears in the Parent area solely after a request actually failed. The locally collected recovery evidence itself stays aggregate-only (per-surface counts and outcome classes; never identifiers, signed payloads, account or session values, wallet data, or raw errors) and local to the device; `CloudRecoveryEvidenceTests` pins that shape. The App Store review monitor's exact-cycle arming contract is owned by `docs/app-store-review-monitor.md`; the shared GET-only monitor reads `APP_REVIEW_MONITOR_VERSION` and reuses the existing submit App Store Connect key, never a dedicated `ASC_REVIEW_MONITOR_*` credential. Prove a candidate `app-review-submit` pin against Eddie's real App Store state with `.github/workflows/app-review-monitor-e2e.yml` (`tools/app-review/observe_review_status.js` calls `observeReviewStatus` only - never `monitor`/`status`, and never writes a GitHub issue); bump `app-review-monitor.yml`'s checkout pin only after that live run returns the expected terminal class. `docs/app-review.md` is authoritative for the App Review submission pipeline, including its captain gates, engine pin, credential lanes, assemble-upload-submit order, hands-off bar, and first-release recovery behavior. `tools/app-review/README.md` owns only the module boundaries. Keep `test/app-review-lanes-test.py` passing when touching those workflows, and never invoke `app_review_pipeline.js submit` from Eddie.
