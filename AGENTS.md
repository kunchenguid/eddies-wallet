# Project agent memory

This public repository is the frontend and product home for Eddie's Wallet. Keep client behavior aligned with the product requirements in `docs/product-requirements.md`, especially split-audience money language, parent/child permissions, and offline states. The root `README.md` is the public landing page; keep its status, setup, and limitation claims truthful for an unfinished, unreleased MVP.

The app's service implementation and operations are maintained separately. Keep this repository frontend-only: do not add backend source, migrations, credentials, deployment assets, or infrastructure configuration here.

Brand and interface guidance lives in the project skill at `.agents/skills/eddies-wallet-design/SKILL.md`; load it before changing visuals, copy, or assets. `.claude/skills` is a tracked relative symlink to `.agents/skills`, so keep skill directory names matching their `name:` frontmatter and keep file names exact-cased for case-sensitive checkouts.

Releases ship through release-please and a captain-merged release PR that uploads to TestFlight; `docs/release.md` is authoritative for the pipeline, including the pull-request Release compile regression, version lineage, trust boundaries, and Apple-side setup. `docs/app-store-configuration.md` is authoritative for the live App Store Connect state of the optional Cloud subscription - products, prices, plan type, grace period, notification URLs, and what is deliberately still unproven. Apple account-level setup is shared across several apps and already satisfied; never request an agreement, tax/banking, upload API key, or distribution certificate again, and keep `EddysWallet/Configuration/EddysWallet.storekit` in step with that record. `docs/privacy-policy.md` is an unpublished captain-review draft describing only verified app behavior; keep it truthful against the code and keep its open-questions section rather than guessing, and do not treat it as a published policy URL. Merging a release PR is the release trigger and belongs to the captain alone. `test/release-checks.sh` guards the workflow invariants, state-aware release-please lineage (pre-first `0.0.0` seed + `initial-version: 0.1.0`, and post-first advanced seed matching available CHANGELOG/tag lineage), and version derivation; run it (plus the normal test suite) after touching anything under `.github/`, `ExportOptions.plist`, `release-please-config.json`, `test/fixtures/release-lineage/`, or the version files release-please owns (`version.txt`, `.release-please-manifest.json`, `CHANGELOG.md` - never hand-edit those three).

The app is kid-first: the child's read-only wallet is the root, and parent access is a transient in-memory elevation (`WalletStore.elevation`) that must never be persisted or survive backgrounding. `docs/product-requirements.md` owns split-audience money language, external-brand placement, child-personal everyday chrome, Parent terminology, and excluded product surfaces; brand and profile-derived runtime strings live in `ProductBrand` and `ChildProfileCopy`. Cloud runtime write settlement lives in `CloudWalletRepository` and the replica metadata in `LocalWalletRepository`: a persisted replica must first confirm its revision with a successful server read, at most one exact request, revision, and idempotency key may remain unresolved, and neither another write nor a Cloud-to-local handoff may proceed until stable server entry identity or accepted revision proves observation. `EddysWallet/README.md` owns wallet-read concurrency and publication ordering; keep every published-state branch in `WalletStore.refresh` aligned with that contract. Parents edit the child nickname only inside the Parent area (`EditChildProfileView` / `WalletStore.updateChildProfile` via `PUT /v1/child`); the kid home never exposes profile editing. Parent action buttons use `ActionButton`/`ActionButtonMetrics` with one continuous rounded geometry for fill and hit target - do not reintroduce `.buttonStyle(.bordered)` behind a mismatched card background. Parent PIN entry never scrolls - `ParentGateView` sizes the keypad to the screen and reserves its status line - and every `MoneyFlowView` step pins its primary action in a bottom safe-area inset so no confirm control can fall below the fold; both own those contracts in their own doc comments. Signed-in simulator and UI-test states use the Debug-only launch seam in `EddysWallet/DebugScenarios.swift`; that file owns its supported environment variables, and tests must never use real accounts. Follow the evidence-directory environment contract documented on `EvidenceCaptureUITests` when capturing labeled screenshots. The shared scheme's `StoreKitConfigurationFileReference` only applies when Xcode itself launches the app: under `xcodebuild` (so all of CI) StoreKit ignores it and resolves the live App Store sandbox catalog over the network, so UI tests must never bound how long a product query takes - wait for the diagnostics surface to leave `CloudDiagnosticsStatus.loading` and judge the terminal status, as `terminalStoreKitDiagnosticsStatus` does. Every `HTTPTransport` test double must be genuinely thread-safe: `data(for:)` is nonisolated and `WalletStore` starts unstructured refresh tasks, so the app reaches a double from several cooperative threads at once exactly as it reaches `URLSessionTransport`, and unsynchronised stored properties corrupt their own buffers and kill the test host with SIGSEGV instead of failing an assertion. When a test process exits with no reported failure, rerun with `xcodebuild test -enableThreadSanitizer YES` scoped to the named test before suspecting the runner. `EddysWallet.xcodeproj/project.pbxproj` is hand-maintained with deterministic hex IDs; follow the existing ID conventions when adding files or targets.

Cloud capability behavior and client session presentation are documented in `EddysWallet/README.md`; the live StoreKit/backend distinction is owned by `docs/app-store-configuration.md`. No shipped surface leads a parent into diagnostics: both the StoreKit and Cloud-recovery readouts are Debug-only and reachable solely through `EW_UITEST_DIAGNOSTICS=1` (`DebugLaunchScenario.showsDiagnosticsEntryPoints`). The locally collected recovery evidence itself stays aggregate-only (per-surface counts and outcome classes; never identifiers, signed payloads, account or session values, wallet data, or raw errors) and local to the device; `CloudRecoveryEvidenceTests` pins that shape. The App Store review monitor's exact-cycle arming contract is owned by `docs/app-store-review-monitor.md`.
